# День 13. Состояние задачи (Task State Machine)

Агент, у которого задача — не диалог, а объект с формализованным состоянием.
Состояние лежит в `tasks/<id>.json`, каждая команда читает его с диска и
пишет обратно, поэтому работу можно прервать в любой момент и продолжить
из другого запуска.

## Автомат

```
STAGE:   planning ──▶ execution ──▶ validation ──▶ done
                          ▲              │
                          └──────────────┘  не прошло проверку

STATUS:  active ◀──▶ paused ──▶ finished
```

Пауза — не этап, а флаг поверх этапа. Если сделать `paused` отдельным
состоянием, при остановке потеряется точка возврата: неоткуда узнать,
в `execution` мы стояли или в `validation`.

Три обязательных поля из задания:

| Поле | Где в коде | Пример |
|---|---|---|
| этап задачи | `stage` | `execution` |
| текущий шаг | `current_step` + `steps[]` | `3. Сделать прототип` |
| ожидаемое действие | `expected_actor` + `expected_action` | `agent — выполнить шаг 3` |

## Структура

```
day13-task-state-machine/
├── config.py        приватный ключ: .env + скрытый ввод, в терминал не попадает
├── state.py         TaskState: этапы, переходы, шаги, сохранение на диск
├── llm.py           AITunnel + mock-режим
├── agent.py         CLI: new / plan / step / run / check / pause / resume / status / list
├── demo.py          полный сценарий через отдельные процессы
├── report.py        генерация RESULTS.md
├── run.ps1          демо + отчёт одной командой
├── .env.example     шаблон конфигурации
├── .gitignore       .env, tasks/, output/ не уходят в репозиторий
└── tasks/           состояния задач (создаётся при работе)
```

## Быстрый старт

```powershell
py -3 .\config.py --set-key      # ключ вводится скрыто, пишется в .env
py -3 .\config.py --check        # покажет только маску sk-aitunnel...4417
.\run.ps1 -Mock                  # прогон без API
.\run.ps1                        # реальный прогон
```

## Работа вручную

```powershell
py -3 .\agent.py new "Подготовить отчёт по продажам за квартал"
py -3 .\agent.py plan   task-20260916-120000
py -3 .\agent.py step   task-20260916-120000
py -3 .\agent.py pause  task-20260916-120000 --reason "конец дня"
py -3 .\agent.py status task-20260916-120000
py -3 .\agent.py resume task-20260916-120000
py -3 .\agent.py run    task-20260916-120000
py -3 .\agent.py check  task-20260916-120000
py -3 .\agent.py list
```

## Продолжение без повторных объяснений

После паузы в модель уходит `resume_brief()` — цель, план с отметками, результаты
последних шагов, текущий шаг и ожидаемое действие. Не весь диалог. Поэтому:

- пользователю не нужно заново описывать задачу,
- модели не нужен прошлый контекст,
- стоимость продолжения фиксированная и не растёт вместе с историей.

В отчёте это сравнивается с наивным вариантом (`full_history_context`) — пересказом
всего, что происходило.

## Приватность ключа

Ключ хранится в `.env`, который перечислен в `.gitignore`. Ввод идёт через
`getpass` — символы не отображаются и не попадают в историю PowerShell.
`config.py --check` показывает только маску. Команду вида `$env:KEY="sk-..."`
использовать не нужно: она сохраняется в истории консоли.
